Does my bug-hunting agent find the bugs I hide?

A test of one AI reviewer, and what happened when I changed something about it.

What it tests

My bug-hunting agent reads the code that merged since its last look and suggests up to 3 possible bugs. This test asks one question: when a known bug is there, how often is it caught?

How the test works

  • 9 hidden bugs. A script folds each one into a real Violencetown change, so it looks like part of that change. Most copy a kind of bug the agent has really found before.
  • 1 obvious bug, to check that the test itself works. The agent caught it 3 of 3 times before the change and 3 of 3 after.
  • 1 real past bug, replayed. It missed it every time, before and after.
  • 3 tries per bug, because the agent can answer differently each time.
  • A range around every result. Each rate comes with a 95% range, and the before-and-after difference gets its own range. If that range includes zero, it is called no clear change. These ranges treat all 27 tries as independent, but tries on the same bug tend to go all one way, so the honest margins are wider than shown.

Before and after

The change was 1 added instruction, telling the agent to check each changed piece of code against its own comment, the spec it implements and the test meant to catch it.

Before21 of 27range 59–89%
After the added instruction20 of 27range 55–87%

A drop of 4 points, with a range from −26 to +19. No clear change.
With 27 tries a side, only a move of about 25 points or more would show up.

What it tells me

  • The added instruction didn’t help, and misses didn’t move.
  • In nearly every miss, the agent read the line with the bug on it and passed it anyway.
  • On real code with nothing hidden in it, it made 1 suggestion in 6 runs before the change and 4 in 6 after. 3 of those 4 pointed at 2 real Violencetown bugs nobody knew about. The other was a false alarm.
  • The next test, already set up, changes what the agent has to write down about each piece of code.

What could be off

All of the before runs used an older setup than the after runs. A 6-run check in the newer setup matched the old results 6 of 6, but a full rerun would be cleaner. Claude read every graded run in full, on top of the automatic grading.
