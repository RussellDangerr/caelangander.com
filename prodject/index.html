Prodject

Prodject is how I build projects with AI agents, and how I check that they’re working well. I write the idea cards and answer the questions only I can answer. An agent breaks each idea into small changes, each with a checklist, and I approve the checklist. One agent builds each change, a second checks every item against the tests or points me to a screenshot, and I decide what is shipped to production. AI agents write all of the code.

What it has built

My games Violencetown and Grawlix both run on it. Since each game picked up the loop in late October, about 220 changes have merged into Violencetown and about 120 into Grawlix.

How I test the agents

Agents report success with the same confidence whether or not it’s true, so I test them the way I’d test anything else. I’ve run tests where I hide known bugs in real code and count how often an agent finds them.

My bug-hunting agent reads new code and reports what looks wrong. I had 9 bugs hidden in real Violencetown changes and ran it 3 times on each. It found them 21 of 27 times. It missed 1 bug every time, even though it read the line the bug was on.

Then I added 1 instruction, telling it to check each change against its comment, its spec and its test. It found them 20 of 27 times. That’s no clear difference, so the instruction didn’t ship.

Two honest limits. A test of 3 runs on 9 bugs is small, and the runs before the change used an older setup than the runs after. I’d want a cleaner rerun before trusting either number.

On real code with nothing hidden in it, the same agent found 2 Violencetown bugs nobody knew about, and raised 1 false alarm.
